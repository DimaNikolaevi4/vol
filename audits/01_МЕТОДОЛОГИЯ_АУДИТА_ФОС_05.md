# Методология аудита ФОС — файл 05 (итоговая аттестация)

> **Назначение:** правила проверки и исправления файла 05 (ФОС итоговой аттестации) — 15 билетов × 20 вопросов, матрица ответов.
>
> **Главная цель:** обеспечить **однозначность правильного ответа** — не может быть двух правильных или сомнительных вариантов.
>
> **Область применения:**
>
> | Профессия | Код ОКПДТР | Разряды |
> |---|---|---|
> | Наладчик КИПиА | 14919 | 4–5 (П/ПП), 6–7 (КПК) |
> | Слесарь КИПиА | 18494 | 2–3 (П/ПП), 4–6 (КПК) |
> | Оператор станков | 15474 | 2–3 (П/ПП), 4 (КПК) |
>
> **Виды обучения:** П (подготовка), ПП (переподготовка), КПК (повышение квалификации).
>
> **Методология для файлов 03/04** — см. `01_МЕТОДОЛОГИЯ_АУДИТА_ФОС_03_04.md`.

## 2. Правила оформления файла .docx

### 2.1 Шрифт и форматирование

| Параметр | Значение |
> |---|---|
> | Шрифт | Times New Roman |
> | Размер | 14 пт |
> | Выравнивание вопросов | По левому краю |
> | Выравнивание вариантов | По ширине |
> | Выравнивание ответа | По ширине, с отступом слева 0,5 дюйма |
> | Межстрочный интервал | Одинарный |

### 2.2 Шапка документа

**Таблица утверждения (ПРИНЯТО / УТВЕРЖДАЮ):**

| ПРИНЯТО и рекомендовано к утверждению решением педагогического совета | | УТВЕРЖДАЮ: Директор ООО УЦ «ПрофСтрой» ___________ |
> |---|---|---|
> | | | |

**Заголовок (после таблицы, по центру, жирный):**

```
Фонд оценочных средств
итоговой аттестации
по основной программе профессионального обучения
(профессиональной подготовки)                                           [для П]
по профессии «Оператор автоматических и полуавтоматических станков и линий станков»
```

Вид обучения в скобках:
- П → `(профессиональной подготовки)`
- ПП → `(профессиональной переподготовки)`
- КПК → `(повышения квалификации)`

**Подзаголовок:**
- Для 05 (оригинал): `Тестовые задания с выбором одного правильного ответа (20 вопросов)`
- Для 05-N (часть): `Тестовые задания с выбором одного правильного ответа (20 вопросов, часть N из 5)`

### 2.3 Формат вопроса и вариантов

```
1. Текст вопроса?
A) вариант первый;
B) вариант второй;
C) вариант третий;
D) вариант четвёртый.
    Правильный ответ под номером: B
```

**Правила:**
- Вопрос — обычный абзац (Normal), выравнивание по левому краю
- Варианты — отдельные абзацы (List Paragraph), выравнивание по ширине, **с явными латинскими префиксами** A) B) C) D)
- Варианты разделяются точкой с запятой (;), последний — точкой (.)
- Правильный ответ — отдельная строка с отступом: `Правильный ответ под номером: X`
- Обозначения вариантов: **A, B, C, D** (заглавные латинские)
- A = первый вариант, B = второй, C = третий, D = четвёртый

### 2.4 Структура оригинального файла 05

1. Шапка (п. 2.2)
2. Подзаголовок
3. **Таблица 2** — ключи: все 20 уникальных вопросов с правильными ответами
4. **Билеты 1–15** — каждый содержит 20 вопросов
5. **Таблица 3** — матрица ответов 15×20

**Билеты:** каждый билет начинается с заголовка `Билет №N`, содержит 20 вопросов по формату из п. 2.3.

**Матрица ответов** — таблица после всех билетов:

| Билет | 1 | 2 | 3 | ... | 20 |
> |---|---|---|---|---|---|
> | 1 | A | B | C | ... | D |
> | ... | | | | | |
> | 15 | | | | | |

Значения в матрице: только A, B, C, D.

### 2.5 Структура файла 05-N (часть)

Каждый файл 05-N является **автономным .docx** со следующей структурой:

1. **Шапка** — идентична файлу 05 (п. 2.2), в заголовке добавляется пометка `(часть N из 5)`
2. **Подзаголовок** — `Тестовые задания с выбором одного правильного ответа (20 вопросов, часть N из 5)`
3. **Таблица ключей** — все 20 уникальных вопросов с правильными ответами (Таблица 2 из оригинала)
4. **Билеты (3 шт.)** — нумерация сохраняется из оригинала (05-1: билеты 1–3, 05-2: билеты 4–6 и т.д.)
5. **Матрица ответов (3×20)** — только для билетов данной части

> **Нумерация билетов** в файлах 05-N **сохраняет оригинальные номера** из файла 05 (не перенумеровывается с 1).

## 3. Критерии проверки

### Иерархия критичности

| Приоритет | Код | Название | Что проверяется | Детекция |
> |---|---|---|---|
> | **Критический** | **M** | Многозначность | Два и более вариантов могут быть правильными при разных трактовках | ИИ |
> | **Критический** | **S** | Подмена понятий | Термин в вопросе не соответствует термину в НПА, или правильный ответ использует другой термин | ИИ |
> | **Критический** | **E** | Ошибка ключа | Указанный правильный ответ фактически неверный (в ключе вопроса или в матрице) | ИИ + авто |
> | Высокий | **H** | Подсказка | Ключевое слово из вопроса встречается только в одном варианте, и это правильный ответ | Авто |
> | Высокий | **L** | Асимметрия длины | Правильный ответ >1,8× длиннее среднего дистрактора | Авто |
> | Средний | **A** | Размытая формулировка | Слова-размыватели: «обычно», «может», «как правило», «чаще всего», «иногда», «возможно» | Авто |
> | Средний | **N** | Нет привязки к НПА | Правильный ответ не подтверждён нормативным документом из `norma/` | ИИ |
> | Низкий | **D** | Перекос распределения | Буквы правильных ответов распределены неравномерно | Авто |

### 3.1 M — Многозначность (Критический)

**Определение:** существуют два и более варианта, которые можно обосновать как правильные при разумных трактовках вопроса.

**Типичные случаи:**
- Родо-видовые отношения: «сталь» и «углеродистая сталь» — оба верны
- Разные НПА дают разные ответы на один и тот же вопрос
- Вариант формулировки «в том числе» покрывает другой вариант
- Вопрос допускает несколько интерпретаций условия
- Формулировка «допускается» вместо «основной» / «следует применять» — раскрывает несколько правильных

**⚠️ Критическое правило при проверке M:**
- Если ИИ утверждает «вариант X не допускается / снят с производства / не применяется» — **обязана** подтвердить это конкретным пунктом НПА из `norma/`
- Запрещено полагаться на «общие знания» или assumtions о статусе типа оборудования/документа
- Нельзя объявить дистрактором тип, который фактически допускается действующими нормами

**Действие:** переформулировать вопрос так, чтобы только один вариант был однозначно верным, или заменить дистрактор на тип, который однозначно не допускается НПА.

### 3.2 S — Подмена понятий (Критический)

**Определение:** термин в вопросе или в правильном ответе не соответствует терминологии НПА.

**Действие:** привести формулировку в соответствие с НПА.

### 3.3 E — Ошибка ключа (Критический)

**Определение:** указанный в ключе/матрице правильный ответ фактически неверен.

**Детекция (двухуровневая):**

**Уровень 1 — Формальный (авто):**
- Ключ в матрице содержит только A, B, C, D
- Все ячейки матрицы заполнены (нет пропусков)
- Для каждого билета: матрица совпадает с фактическим правильным ответом в вопросе

**Уровень 2 — Содержательный (ИИ, ОБЯЗАТЕЛЕН):**
- Для каждого **уникального** вопроса: прочитать текст варианта, на который указывает ключ, и **подтвердить что именно этот текст является правильным ответом**
- Проверка: «Если бы я не знал ключ, а ответил по знанию предмета — я бы выбрал тот же вариант?»

**⚠️ Критическое правило:** после любой перестановке вариантов (rebalancing) — **обязательно** повторить уровни 1 и 2. Перестановка вариантов без обновления ключа = гарантированный E-дефект.

**Действие:** исправить ключ на букву, соответствующую фактическому правильному варианту.

### 3.4 H — Подсказка (Высокий)

**Определение:** значимое слово (≥4 символов, не стоп-слово) из текста вопроса встречается только в одном варианте ответа, и этот вариант является правильным.

**Алгоритм авто-детекции:**
1. Извлечь из вопроса все значимые слова (исключить стоп-слова)
2. Для каждого слова посчитать, в скольких вариантах оно встречается
3. Если слово встречается только в одном варианте, и этот вариант — правильный → дефект H

**Действие:** переформулировать вопрос или варианты, убрать корневое совпадение.

### 3.5 L — Асимметрия длины вариантов (Высокий)

**Порог:** длина правильного варианта >1,8× средней длины трёх остальных.

**Норма:** доля таких вопросов ≤10% от общего числа.

**Действие:** сократить правильный ответ или расширить дистракторы до сопоставимой длины.

### 3.6 A — Размытая формулировка (Средний)

**Список слов-размывателей:** «обычно», «как правило», «чаще всего», «в основном», «может», «возможно», «иногда».

**Действие:** убрать слово-размыватель и сформулировать вопрос категорично.

### 3.7 N — Нет привязки к НПА (Средний)

**Определение:** правильный ответ не подтверждён конкретным пунктом нормативного документа из `norma/`.

**Нормативная база (`norma/`):**

| Подпапка | Документы |
> |---|---|
> | `common/` | ПУЭ изд.7, ПТЭЭП 2023, ПОТ ЭЭ, Приказ Минтруда 903н, ГОСТ 2.301-68, 2.303-68, 2.305-2008, Р 2.104-2023, 12.1.004-91, 12.4.026-2015, 29322-2014, 8.417-2024 |
> | `kipia/` | ФЗ-102, ФЗ-18, ГОСТ 8.401-80, 8.568-2017, 21.208-2013, 31565-2012, 31610.0-2014, 31996-2012, Р 52931-2008, Р МК 61784-1-2016, Р МЭК 60079-14, Р МЭК 60079-17, Р МЭК 61158, ТР ТС 012-2011, РМГ 29-2013, РД 153-34.0-35.301-2002 |
> | `operator/` | ГОСТ 1050-2013, 19265-73, 24705-2004, 14959-2016, 25346-2013, 25347-2013, 2789-73, 868-82 |

**Действие:** подобрать вопросу НПА-обоснование. Если ответ не подтверждён ни одним НПА — заменить вопрос.

### 3.8 D — Перекос распределения (Низкий)

**Определение:** буквы правильных ответов распределены неравномерно.

**Пороги для 05-N (часть, 3 билета × 20 вопросов = 60 ячеек):**
- Глобально по части: каждая буква 15–35% (9–21 из 60)
- По каждому билету: каждая буква ≤40% (≤8 из 20)
- D-перекос оценивается **локально** (только по этим 3 билетам)

**Итоговый D-контроль** — после сборки всех частей обратно в 05 (глобально 15×20 = 300):
- Глобально: каждая буква 20–30% (60–90 из 300)
- По каждому билету: каждая буква ≤40% (≤8 из 20)

**Действие:** переставить варианты в вопросах с перекосом. При перестановке — **обязательно обновить матрицу** (см. §5.3).

## 4. Порядок проведения аудита

### Шаг 1. Извлечение данных из оригинального 05

1. Прочитать файл 05.docx
2. Извлечь все 20 уникальных вопросов из пре-секции (Таблица 2) с ключами
3. Извлечь 15 билетов (каждый — 20 вопросов)
4. Извлечь матрицу 15×20 (Таблица 3)
5. Сохранить в JSON для дальнейшей работы

### Шаг 2. Разбивка на 5 частей

1. Из JSON создать 5 файлов .docx (05-1 … 05-5) по структуре из п. 2.5
2. Каждый файл содержит: шапку, пре-секцию, 3 билета, матрицу 3×20
3. Пуш 5 файлов в репозиторий

### Шаг 3. Автоматические проверки (для каждой части 05-N)

| Проверка | Что делается |
> |---|---|
> | H — Подсказки | Для каждого вопроса: извлечь значимые слова, проверить уникальность в вариантах |
> | L — Асимметрия | Длина правильного варианта / средняя длина дистракторов |
> | A — Размытость | Поиск слов-размывателей в тексте вопроса |
> | D — Перекос | Подсчёт распределения букв ответов (локально: 3×20=60) |
> | E (матрица) | Все значения A/B/C/D, нет пропусков, совпадение с ключами в билетах |
> | D по билетам | Распределение в каждом билете ≤40% |
> | Uc — Покрытие | Доля уникальных вопросов (оценивается глобально по всем 15 билетам) |
> | U — Дублирование | Один вопрос ≤3 повторов в разных билетах (глобально) |

### Шаг 4. ИИ-проверки (M/S/E/N) + верификация ключа

Для каждого **уникального** вопроса (проверяются один раз, применяются ко всем билетам):

1. **E-содержание (ПЕРВЫМ):** прочитать вопрос, 4 варианта, ключ. Проверить что **текст варианта по указанному ключу** является правильным ответом.
2. **M — Многозначность:** может ли быть >1 правильного? Любое утверждение «X не допускается» должно быть подтверждено цитатой из НПА.
3. **S — Подмена понятий:** соответствует ли терминология НПА?
4. **N — Привязка к НПА:** на какой конкретно документ и пункт опирается правильный ответ?

**⚠️ Порядок важен:** E проверяется первым.

## 5. Исправление файла

### 5.1 Принципы

1. Исправления вносятся в **уникальные вопросы** — изменение автоматически применяется ко всем билетам, где этот вопрос встречается
2. Заменённые вопросы вписываются **на те же номера** — нумерация не сдвигается
3. Замены формируются с привязкой к конкретному пункту НПА из `norma/`
4. Формат нового вопроса строго по п. 2.3
5. После замены — повторный аудит (Шаги 3–4) по исправленному файлу 05-N

### 5.2 Формат исправленного файла

Итоговый 05-N.docx полностью соответствует п. 2 (шрифт, структура, оформление). Файл перезаписывается на месте.

### 5.3 ⚠️ Правило перестановки вариантов (rebalancing)

При перестановке вариантов в 05-N **ключей в тексте вопросов нет** — ключи только в матрице. Поэтому:

1. **Записать до перестановки:** номер уникального вопроса, текст правильного варианта, его позиция в матрице для каждого билета
2. **Переставить варианты** (текст перемещается на новую позицию во всех билетах, где вопрос встречается)
3. **Обновить матрицу** — для каждого билета, где вопрос присутствует, обновить ячейку матрицы чтобы она указывала на **новую позицию** правильного текста
4. **Верифицировать:** для каждого билета распечатать вопрос + все 4 варианта + ячейку матрицы и убедиться, что матрица указывает на правильный текст

**Запрещено:** менять матрицу без перемещения текста, или перемещать текст без обновления матрицы.

**Контрольный пример (в контексте билета):**
```
Было:  A) Собака   B) Кошка   C) Рыба   D) Птица   Матрица[билет][Q] = C (Рыба)

Переставляем C и D:
Стало: A) Собака   B) Кошка   C) Птица   D) Рыба   Матрица[билет][Q] = D (Рыба)
           ↑ текст переместился                        ↑ матрица обновлена
```

## 6. Цикл работы с ФОС 05

```
1. Извлечение данных из оригинального 05 → JSON
   (парсинг: 20 уникальных вопросов, 15 билетов, матрица 15×20, ключи)

2. Разбивка на 5 частей:
   05-1 (билеты 1-3), 05-2 (4-6), 05-3 (7-9), 05-4 (10-12), 05-5 (13-15)

3. Генерация 5 файлов .docx (05-1 … 05-5) с полной структурой (п. 2.5)

4. Пуш 5 файлов в репозиторий

5. Для каждой части 05-N (независимо, в любом порядке):
   а) Авто-проверки (Шаг 3) → ИИ-проверки (Шаг 4) → Протокол дефектов
   б) Исправление дефектов → обновлённый 05-N.docx
   в) Повторный аудит → подтверждение устранения
   г) Пуш обновлённого 05-N в репозиторий

6. После завершения всех 5 частей:
   а) Финальная сборка: объединение 05-1…05-5
      в единый файл 05 (15 билетов + матрица 15×20)
   б) Резервная копия → файл 105
   в) Пуш 05 и 105 в репозиторий
```

> **Принцип:** каждая часть 05-N обрабатывается как самостоятельный ФОС-файл.
> Аудит, исправление и пуш делаются **по частям**, что позволяет работать с объёмом
> 60 ячеек матрицы вместо 300, и не упираться в лимиты контекста.

## 7. История ошибок и извлечённые уроки

> Этот раздел ведётся accumulatively. Каждая ошибка, найденная после «финального» аудита, записывается здесь как правило.

### 7.1 Ошибка: ключ не обновлён при перестановке вариантов (2026-08-13)

**Ситуация:** При rebalancing Q7 вариант «Рабочий чертёж детали» был перемещён с позиции C на D, но ключ остался C. Ключ указывал на «Кинематическую схему».

**Причина:** отсутствовала верификация «ключ → текст варианта по ключу».

**Урок:** добавлен E-уровень-2 (содержательная верификация ключа) и §5.3 (правило перестановки).

### 7.2 Ошибка: ложное утверждение о статусе типа оборудования (2026-08-13)

**Ситуация:** В Q3 дистрактор «Хладоновый» был оставлен на основании утверждения «хладоновые огнетушители сняты с производства». По ППР РФ хладоновые огнетушители допускаются для электроустановок.

**Причина:** ИИ оперировал assumption вместо верификации по НПА.

**Урок:** любое утверждение «не допускается / снят / не применяется» должно быть подтверждено конкретным пунктом НПА.

### 7.3 Ошибка: обработка 05 целиком превышает лимиты контекста (2026-08-13)

**Ситуация:** Файл 05 содержит 15 билетов × 20 вопросов = 300 ячеек матрицы. Попытка выполнить полный цикл аудита и исправления в одной сессии привела к исчерпанию контекста до создания выходных файлов.

**Причина:** объём данных (71 уникальный вопрос, 29 D-перестановок, 11 H-фиксов, 1 A-фикс, генерация .docx с 15 билетами и матрицей 15×20) превысил возможности одной сессии.

**Урок:** добавлено правило §6 — файлы 05 **обязательно разбиваются** на 5 частей (05-1…05-5) по 3 билета каждая. Каждая часть обрабатывается независимо.
