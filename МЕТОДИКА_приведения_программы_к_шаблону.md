# Методика приведения программы ПО к шаблону УМК

Рабочая инструкция для приведения основных программ профессионального обучения
(и любых их версий) к шаблону УЦ «ПрофСтрой» — так, чтобы результат проходил
методическую проверку с первого раза.

Проверено на: `00.Программа_ПО_ПК_КИП.docx` (КПК 18494 «Слесарь по КИПиА», 144 ч)
по шаблону `ШАБЛОН_ПО_П__УМК_16.09.2026.docx`, ориентир — `00 Программа_ПО_ПП_КИП стар.docx`.

Путь к шаблону при работе: `E:\github\vol\ШАБЛОН_ПО_П__УМК_16.09.2026.docx`
(в скриптах он же — `TPL`).

**Карточка программы:** ПС 275 (приказ Минтруда от 14.04.2025 № 239н), ЕТКС выпуск 2, § 94–96,
**4–6 разряд**, **72 академических часа**, в том числе **38 часов производственной практики**,
срок — **две недели (10 учебных дней)**. Эти цифры берутся из учебного плана и повторяются
на титуле, в паспорте и в оглавлении — при любом расхождении правим по плану.

**Правило зелёного.** В шаблоне зелёным подсвечено то, что переносится **один в один**
(дословно, вместе с нумерацией). Всё остальное — обсуждаемое: формулировки и наполнение
берутся из программы и старой версии. При конфликте: зелёное → шаблон, остальное → содержание программы.

Обязательные (зелёные) пункты — см. §3.

   `Категория слушателей:`, `Объем:`, `Форма обучения:`, `Наименование профессии рабочего, должность служащего:`, `Уровень квалификации:`.

должны совпадать с часами в учебном плане и с разрядами в паспорте. Пример: 144 часа, 2–3 разряд.

### 2.1. Паспорт (§1.1) — источники по строкам

Правило владельца (зафиксировано 19.11.2026):

| Строка паспорта | Откуда берём |
|---|---|
| Заголовок «Паспорт» | уже правильный, не трогаем |
| Нормативно-правовая основа | п. 1–6 — из шаблона буква в букву; п. 7–8 — из старой программы; п. 9 — из шаблона (ФГОС СПО), **если он есть для этой профессии** |
| Объем программы | **цифры** — из учебного плана программы, **текст** — из шаблона |
| Срок реализации программы | из учебного плана программы |
| Форма обучения | из шаблона |
| Режим занятий | из шаблона |
| Требования к образованию и обучению | из старой программы |
| Требования к опыту практической работы | из старой программы |

Ширины колонок паспортной таблицы — как в шаблоне: `1668` + `8397` twips (tblW `10065`).

**Ловушки:**
- в старой версии нормативная основа может быть на 8 пунктов — девятый (ФГОС) всё равно берётся из шаблона;
- нумерация в строке «Нормативно-правовая основа» — сквозная **1…N**, цифры ставятся в текст пункта;
  при переносе пунктов из разных источников перенумеровать заново (1–6 шаблон, 7–8 старая, 9 шаблон);
- **пункт 9 (ФГОС СПО) есть не всегда.** Его добавляют, только если для профессии действует
  подходящий ФГОС СПО. Пример: в папке
  `E:\github\vol\Оператор автоматических и полуавтоматических станков и линий станков`
  девятого пункта нет — там нормативная основа заканчивается восьмым. В остальных папках
  (в том числе «Слесарь по КИПиА») пункт 9 обязателен. Поэтому количество пунктов — 8 или 9,
  и нумерация строится по факту, без «дыр»;
- если часы в паспорте не сходятся с титулом, это не повод править паспорт: сначала выясняется,
  какой объём верный (титул и учебный план должны совпадать).

### 2.2. §1.2 Планируемые результаты

Структура — из шаблона, содержание — из старой программы.

| Таблица | Подпись |
|---|---|
| Таблица 2 | Планируемые результаты освоения программы |
| Таблица 3 | Сопоставление единиц ФГОС СПО и профессионального стандарта (как в шаблоне: колонки «ФГОС СПО по смежной профессии» / «ПС» / «Выводы») |
| Таблица 4 | Результаты освоения программы повышения квалификации |
| Таблица 5 | Определение результатов освоения программы на основе профессионального стандарта |
| Таблица 6 | Требования к результатам освоения программы по разрядам (детальная таблица ОТФ/ТФ) |

Правила:
- нумерация сквозная с **«Таблица 2.»** — «Таблица 1» в шаблоне отсутствует, не добавлять;
- дубли номеров — ошибка, которую надо ловить сразу (встречалась: две «Таблицы 2»);
- подпись — два абзаца: `Таблица N.` (по правому краю) и название (по центру);
- шапки таблиц — дословно из зелёных ячеек шаблона:
  «Вид программы, профессия, разряд», «Наименование выбранного профессионального стандарта
  (одного или нескольких)», «Уровень квалификации (согласно профстандарту / ЕТКС)»,
  «Виды деятельности», «Профессиональные компетенции, соответствующие видам деятельности»;
- детальная таблица ОТФ/ТФ по разрядам (в старой версии — три таблицы по 7 строк) сводится
  в одну и получает подпись «Таблица 6».

### 2.3. Обозначение вида программы

В шаблоне вид программы обозначается **ПК** (повышение квалификации), рядом с П и ПП
(подготовка, переподготовка). Поэтому:
- в именах файлов — `ПО_ПК_…`, не `ПО_КПК_…`;
- в паспорте строка называется **«Цель и задачи обучения:»**, и из двух блоков шаблона
  («Для П и ПП» / «Для ПК») берётся **«Для ПК»** — от слов «Цель:» до конца задач.

5. Номера страниц в оглавлении не соответствуют тексту (поле не обновлялось после правок).

## 4. Таблицы: ширина, часы, перенос граф

**Ширина.** Полоса набора — 165 мм (`9354` twips: лист 210 − поля 30 слева − 15 справа).
Любая таблица шире 165 мм вылезает на поля и обрезается при печати. В исходной программе
учебно-тематический план и календарный график были 252 мм — их надо сжимать пропорционально
(скрипт делает это автоматически).

**Очная и очно-заочная формы.** В шаблоне учебный план и учебно-тематический план даны
двумя таблицами с одинаковой шапкой:

| Графа | Очная | Очно-заочная |
|---|---|---|
| 5–6 (Очно: теория / практика) | все часы | часы очной части |
| 7–8 (Дистанционно: теория / практика) | пусто | часы дистанционной части |

Правило переноса: `теория_очная = гр.5 + гр.7`, `практика_очная = гр.6 + гр.8`,
дистанционные графы обнуляются. Обратный перенос — не «обмен местами», а именно сложение:
если сложить неправильно, теряются часы практики (встретившаяся ошибка).

**Контроль после правки.** Сумма часов в строке (гр. 5+6+7+8) должна совпадать с исходной,
строка «Итого» — сходиться с учебным планом и титулом (в нашем случае 72 + 38 + 6 + … = 144 ч).

## 6. Порядок работы

1. Сверить титул (объём, разряд, даты приказа и протокола, форма обучения).
2. Сверить структуру заголовков с §3 этого документа.
3. Правка титула и заголовков.
4. Разделить планы по формам обучения (при необходимости) и пересчитать часы.
5. Сжать таблицы шире 165 мм.
6. Открыть файл в Word, согласиться на обновление полей, проверить оглавление (F9 →
   «Обновить целиком»), сверить номера страниц.
7. Постранично вычитать текст (глазами, по одной странице).

## 7. Технические проверки

Автоматика лежит в `work/` (Python + python-docx, lxml):

| Скрипт | Что делает |
|---|---|
| `pages.py` | постраничный дамп текста и типографики (страницы по `lastRenderedPageBreak`) |
| `verify.py` | список заголовков, дубли закладок, таблицы шире 170 мм |
| `check_rows.py` | построчная сверка часов до/после правки |
| `fix1.py` | титул, разделение планов, переименование и нумерация §2–§3 |
| `fix2.py` | чистка дублей закладок, оформление 3.4.1/3.4.2 как заголовков, сжатие таблиц, `updateFields` |

Запуск: `python work\fix1.py` затем `python work\fix2.py`, результат — `work/out/…docx`.
Перед правкой всегда делать копию исходника (`work/backup/`).

**Что проверять в XML, если правишь вручную:**
- дубли закладок `_Toc…` (появляются при копировании заголовков) — Word из-за них ломает оглавление;
- `w:tblW` и `w:tblGrid` — сумма колонок не больше 9354 twips;
- `w:updateFields` в `settings.xml` — чтобы оглавление пересобралось при открытии;
- `outlineLvl` у заголовков — иначе пункт не попадёт в оглавление.
