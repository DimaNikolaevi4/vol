# МЕТОДИКА ПЕРЕНОСА РАЗДЕЛА 1.2 ПРОГРАММЫ ПО НОВОМУ ШАБЛОНУ

Документ фиксирует алгоритм, применённый при обновлении раздела
«1.2. Планируемые результаты освоения программы» в программе повышения квалификации
по профессии 18494 «Слесарь по контрольно-измерительным приборам и автоматике»
(4–6 разряд, 72 часа). Используется как системный промт для автоматической
переработки аналогичных программ.

Источники:
- `ШАБЛОН_ПО_П__УМК_16.09.2026.docx` — эталон структуры и методических формулировок;
- `00.Программа_ПО_ПК_КИП стар.docx` — legacy-источник (прежде всего таблица разрядов);
- `00.Программа_ПО_ПК_КИП.docx` — целевой файл.

## 1. Сопоставление таблиц 2–5 с новым шаблоном

Принцип: **структура и терминология — из шаблона, фактические данные — из нашей программы**.

подставляются наши данные. Нельзя оставлять чужие данные (ПС 961, «Наладчик КИПиА»,
15.01.41, § 272 ЕТКС, «профессиональная подготовка», 75 баллов).

## 2. Таблица 6 «Требования к результатам освоения программы по разрядам»

Шаблон такой таблицы **не содержит** (в нём после Таблицы 5 идёт Таблица 10 —
календарный график, и Таблица 11 — кадровые требования). Поэтому для программ
с несколькими разрядами таблица разрядов **обязательно переносится из legacy-файла**
и не может быть заменена «типовой» таблицей шаблона.

Почему: только legacy-таблица содержит детальные формулировки профессионального
стандарта 275 и ЕТКС для каждого разряда: ОТФ 3.3/3.4/3.5, необходимые знания
и умения, трудовые функции 3.3.1–3.3.3 / 3.4.1–3.4.3 / 3.5.1–3.5.3, трудовые
действия и характеристики работ § 94, § 95, § 96. Сокращение любой ячейки ведёт
к потере требований к квалификации.

Как переносить:
1. В legacy-файле таблица разрядов состоит из отдельной строки заголовков (3 колонки)
   и трёх таблиц 7×3 — по одной на 4, 5 и 6 разряд.
2. Перенести **все 18 строк данных** (6 на разряд: разряд, ПС+ОТФ, знания, 3×ТФ)
   без сокращений и пересказа.
3. Восстановить структуру «чистой» таблицы:
   - единственная строка заголовка с описательными подписями из legacy-файла:
     «Наименование выбранного профессионального стандарта (одного или нескольких),
     ОТФ и (или) ТФ, трудовые действия» / «Необходимые умения/ необходимые знания
     (согласно профессиональному стандарту)» / «Уровень квалификации (согласно ЕТКС)»;
   - удалить повторяющиеся служебные строки «1 | 2 | 3» на стыках блоков;
   - строки «4 разряд», «5 разряд», «6 разряд» — объединить по трём колонкам;
   - сохранить вертикальное объединение ячеек «Уровень квалификации (согласно ЕТКС)»
     и «Характеристика работ» внутри каждого блока;
   - `tblHeader` только у первой строки; ширина таблицы 9340 twips (16,5 см),
     сетка 2646 / 3882 / 2812; при необходимости `cantSplit` для строк.
4. Обязательная проверка: программно сравнить каждую из 18 ячеек данных с legacy
   (результат `identical=True`). Результат текущей конвертации: 19 строк
   (1 заголовок + 18 данных), дублей заголовков нет, все 18 строк совпадают.

## 4. Порядок выполнения конвертации (коротко)

1. Сделать резервную копию целевого файла.
2. Извлечь из legacy три таблицы разрядов и строку описательных заголовков;
   зафиксировать эталонные 18 строк данных.
3. Сверить таблицы 2–5 целевого файла с шаблоном по п. 1 настоящей методики;
   исправить ссылку на ЕТКС на «выпуск 3, § 94–96».
4. Заменить таблицу 6 clean-структурой: описательный заголовок + 18 данных.
5. Проверить программно: 19 строк, 0 дублей «1|2|3», 18/18 ячеек идентичны legacy.
6. Открыть документ в Word, обновить поля и оглавление, визуально проверить
   раздел 1.2 на отсутствие выхода за поля.
7. Зафиксировать изменения в Git явным `git add` двух файлов
   (программа и методика) и `git push`.
